The AWS (`_range.yml`) and GCP (`_gcp-dev.yml`) deploy workflows and `scripts/bootstrap/deploy.py`'s GCP control-plane apply now render the range egress allowlist tfvars from the deployment's `shifter.yaml` (`settings.range_egress`) via `shifter-config render` at plan/apply time, instead of carrying the egress CIDRs in a separately maintained deploy secret. The allowlist is now single-source end-to-end: CI receives `shifter.yaml` as a deployment secret (`SHIFTER_CONFIG_DEV_RANGE` / `SHIFTER_CONFIG_PROD_RANGE` / `SHIFTER_CONFIG_GCP_DEV`), `victim_allowed_cidrs` no longer belongs in `TF_VARS_*_RANGE`, and a missing config fails the deploy loud rather than silently applying `status-quo`. See `docs/dev/deploy-secrets.md`.
