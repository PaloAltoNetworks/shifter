# UX-052: Component documentation

## Statement

Every component in the design system shall have interactive documentation showing every state (default, hover, focus, active, disabled, loading, error) and every variant. Documentation shall be live (running in a browser) and shall be discoverable from the repository root. Documentation shall include accessibility notes for non-obvious patterns.

## Rationale

Component docs are how the design system stays usable: contributors need to see every state at a glance, designers need a reference, reviewers need a baseline. Without live docs the system becomes oral tradition and rots.
